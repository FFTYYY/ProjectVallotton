部署教程

这一章详细介绍怎样把Vallotton部署到一台服务器上。部署以后，你可以在任何地方（包括手机上），通过自己的域名打开Vallotton；画图也在服务器上进行，不需要你的电脑一直开着。这一章假设你会用命令行登录和操作一台Linux服务器。如果你只想在自己的电脑上用，看快速上手就够了。

你需要准备的东西

  • 一台Linux服务器，能从公网访问。下面的命令都以Ubuntu为例。画图是在NovelAI那边进行的，所以服务器不需要显卡。
  • 一个域名。在域名服务商那里添加一条A记录，指向服务器的IP。Vallotton只能通过HTTPS域名登录，直接用IP地址打开是登录不了的。
  • NovelAI和DeepSeek的密钥，和快速上手里要的一样，获取方法见准备两个账号。
  • 在服务器上装好Docker、nginx和certbot。Docker用来运行Vallotton，nginx负责把你的域名接到Vallotton上，certbot用来申请免费的HTTPS证书： 
    curl -fsSL https://get.docker.com | sh
sudo apt install nginx certbot python3-certbot-nginx
  • 在云服务商的控制台里放行22、80、443三个端口（通常在「安全组」或「防火墙」设置里）。22用来登录服务器，80和443用来访问网页。

部署步骤

部署好以后，Vallotton会在服务器上的Docker里运行，只在服务器本机开一个端口（默认是8300）。从外面访问你的域名时，请求先到服务器上的nginx，由它负责HTTPS，再转给Vallotton。下面按顺序来讲解。

1.下载代码

登录服务器，把代码下载到一个固定的位置，比如/srv/vallotton/app。还要建一个目录专门存放画好的图，比如/srv/vallotton/media。后文中会以这两个地址为例，如果要用其他路径，后文中的指令都需要对应地调整。

sudo mkdir -p /srv/vallotton/media
sudo chown -R $USER /srv/vallotton
git clone https://github.com/FFTYYY/ProjectVallotton.git /srv/vallotton/app
cd /srv/vallotton/app

下文的命令都默认在这个代码目录/srv/vallotton/app里运行。

2.填写.env

Vallotton的所有配置都写在代码目录下的.env文件里，包括各种密钥和密码。先从模板复制一份：

cp .env.example .env

然后用编辑器打开它（比如nano .env），修改下面这些项：

项填什么
LLM_PROVIDER用什么语言模型。目前只支持deepseek或grok。模板里默认是deepseek。
DEEPSEEK_API_KEYDeepSeek的API key。只有LLM_PROVIDER选deepseek时需要填。以sk-开头。
GROK_API_KEYGrok的API key。只有LLM_PROVIDER选grok时需要填。以xai-开头。
NOVELAI_API_KEYNovelAI的密钥。以pst-开头。
APP_USERNAME
APP_PASSWORD		登录Vallotton网页用的用户名和密码。
ADMIN_PASSWORD管理后台的密码。通常不会用到，随便设一个长一点的随机密码就行。
DJANGO_SECRET_KEY一串随机字符，用来保护登录状态。
POSTGRES_PASSWORD数据库的密码。你自己不会用到它，同样填一串随机字符即可。
DOMAIN你的域名。不要带https://前缀。例如vallotton.example.com。
MEDIA_DIR存放图片的目录，填上一步建的/srv/vallotton/media。

下面几项不是必填的，但比较常用：

  • OPENROUTER_API_KEY：Openrouter的API key。填了以后，如果语言模型的官方接口连不上，Vallotton会自动暂时切换到OpenRouter备用线路。
  • MCP_TOKEN：MCP的密钥。只有打算开启MCP时需要填。一般填一串随机字符，用到的时候复制即可。
  • 各家的模型型号和推理强度，比如DEEPSEEK_MODEL、GROK_REASONING_EFFORT：想换模型或者调快慢时改。详细列表见后文环境变量一览

其余的项通常保持默认就可以。环境变量的详细列表见最后的环境变量一览。

3.启动

在代码目录下运行：

docker compose up -d --build

第一次启动要下载和构建几个Docker镜像，需要等几分钟。完成以后，用下面两条命令检查一下：

docker compose ps
curl -s http://127.0.0.1:8300/api/auth/me

第一条命令应该列出db、backend、web三个容器，状态都是Up。第二条命令应该返回{"authenticated": false}，说明Vallotton已经在服务器本机的8300端口上跑起来了。

这时还不能从外网访问，因为8300端口只对服务器本机开放。外网访问要经过下一步配置的nginx。如果8300端口已经被服务器上别的程序占用了，可以在.env里把VALLOTTON_HTTP_PORT改成别的端口，然后再运行一次docker compose up -d，下一步中的nginx配置也要跟着改。

4.配置域名和HTTPS

代码里带了一份nginx的配置模板deploy/host-nginx.conf.example，它会把发到你域名上的访问转给Vallotton。下面的命令会自动配置nginx。这个命令以及后文中，我们以vallotton.example.com这个域名为例。运行之前，记得先把命令里的vallotton.example.com换成你的域名。

sudo sh -c 'sed "s/YOUR_DOMAIN/vallotton.example.com/g" deploy/host-nginx.conf.example > /etc/nginx/sites-available/vallotton'
sudo ln -s /etc/nginx/sites-available/vallotton /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

然后用certbot申请HTTPS证书（同样，把示例域名vallotton.example.com换成你的域名）。它会自动修改刚才的配置，加上HTTPS，并且把http的访问自动跳转到https：

sudo certbot --nginx -d vallotton.example.com

证书的有效期是90天，certbot会在到期前自动续期，不需要额外操作。

如果你的域名用了Cloudflare：用certbot申请证书之前，记得先在Cloudflare里把这条记录切成「仅DNS」（灰色的云朵），申请成功以后再切回代理。

也可以选择不用certbot，改用Cloudflare签发的源站证书（Origin Certificate）：在Cloudflare的SSL/TLS → Origin Server里生成，有效期15年，不用续期。把证书和私钥放到服务器上，在nginx配置里加一段443端口的server块指向它们就行。这种证书只在经过Cloudflare代理访问时有效。

不管用哪种证书，Cloudflare的SSL/TLS模式都要选「Full (strict)」，不能选「Flexible」，否则网页能打开，但是登录不了。

5.打开网页

一切顺利的话，在浏览器里打开https://vallotton.example.com（换成你的域名），用.env里设的APP_USERNAME和APP_PASSWORD即可登录Vallotton。之后的用法和快速上手、进阶指南里讲的完全一样。也可以在手机上将Vallotton安装为一个app。见进阶指南的在手机上用。

需要注意的是，一定要通过https和域名访问。如果直接用http或者用服务器的IP打开，那么即使页面能显示，也无法登录。这是为了安全而故意设计的。

日常维护

下面的命令都在代码目录/srv/vallotton/app里运行。

  • 更新到新版本：拉取最新的代码，再重新构建、启动。 
    git pull && docker compose up -d --build
  • 修改配置：改完.env以后运行docker compose up -d就会生效。网页登录的账号和密码也是这样改，每次启动时会自动更新。
  • 查看日志：出了问题想看看发生了什么，可以看后端的日志，按Ctrl+C退出。 
    docker compose logs -f backend
  • 停止：运行docker compose down。对话和图片都会保留，下次docker compose up -d就能继续用。不要加-v，那样会把数据库一起删掉。
  • 备份：Vallotton的全部数据就是数据库和图片目录（图片存在单独的文件夹中，而非数据库内，这是为了提高性能和便于管理）。以下命令备份数据库和图片目录： 
    docker compose exec db pg_dump -U vallotton vallotton | gzip > backup-$(date +%F).sql.gz
tar czf media-$(date +%F).tar.gz -C /srv/vallotton media
    从备份恢复数据库（将日期换成对应的日期后缀）： 
    gunzip -c backup-日期.sql.gz | docker compose exec -T db psql -U vallotton vallotton

Vallotton还带有一个管理后台，能看到所有对话、消息和图片，以及每天的API花费。为了安全，它默认不对外开放，平时也用不到。确实需要的话，只需要在代码目录里新建一个docker-compose.override.yml，给backend加上ports: ["127.0.0.1:8000:8000"]，并在.env里临时设置COOKIE_SECURE=0，重新启动服务。然后用SSH隧道连到服务器，打开http://127.0.0.1:8000/admin/，用ADMIN_USERNAME和ADMIN_PASSWORD登录。用完记得把这两处改回去。

MCP

MCP是Vallotton提供的一套通过url访问内部服务的接口。别的程序可以通过它发一句话并拿回画好的图，也可以直接用提示词画图、查询额度等。通过MCP发起的对话在网页的左边栏里同样能看到。

注意Vallotton这个接口用的是自己的一套魔改版的简易协议，不是标准的MCP协议，所以无法直接在Claude Desktop、Cursor这类客户端中连接（现在MCP也不那么常用就是了...）。

启用方法：

  1. 在.env里设置MCP_TOKEN，填一串任意的字符串。这是你的Vallotton的MCP服务的密钥。
  2. 运行docker compose --profile mcp up -d --build。可以用curl -s http://127.0.0.1:8301/health检查，返回里有"ok": true就说明启动了。
  3. 默认情况下，MCP只在服务器本机的8301端口上。如果想从外网访问，需要在.env里设置MCP_BIND=0.0.0.0，并重新运行上一条命令。记得在云服务商的控制台放行8301端口。

使用MCP时，只需要把如下信息告诉你的coding agent，然后它自会figure out如何与Vallotton的MCP服务交互。

{
  "name": "vallotton",
  "url": "http://服务器IP:8301",
  "bearer_token": "你的.env里的 MCP_TOKEN"
}

有两点需要注意。第一，打开了外网访问的话，从外网直接访问MCP走的是明文HTTP协议。第二，画一张图可能要好几分钟，客户端的超时要设到600秒以上。

关于安全

如果你按照本教程部署，那么Vallotton默认已经做了这些保护：

  • 对外只开放nginx的80和443端口。Vallotton自己的端口和数据库都只在服务器内部，外面访问不到。MCP只有在你设置了MCP_BIND=0.0.0.0时才对外。
  • 网页登录连续输错8次密码，会锁定15分钟。网页登录和管理后台是两个独立的账号。
  • 画好的图也要登录以后才能看到，别人拿到图片的地址也打不开。
  • 上传的图片会经过检查，只接受图片格式，每张不超过15 MB。

你需要自己注意的是：.env里的密码尽量都用随机的长字符串；.env文件不要外传，也不要提交到git；云服务商的控制台里只放行22、80、443，以及你确实要对外开放的MCP端口。

附录：出了问题怎么办

以下是一个简易的问题自查表。

看到的现象原因和处理办法
网页能打开，但是登录不了检查是不是用https://你的域名 打开的，用IP地址或者http打开都登录不了。用了Cloudflare的话，检查SSL/TLS模式是不是「Full (strict)」。服务器的系统时间偏差太大也会导致这个问题。
登录时提示被锁定连续输错8次密码会锁定15分钟，等一会儿再试。
启动时提示端口被占用在.env里把VALLOTTON_HTTP_PORT（或者MCP的MCP_PUBLIC_PORT）改成别的端口，运行docker compose up -d，再把nginx配置里proxy_pass的端口改成一样的，重新加载nginx。
画到一半显示「任务中断」画图的过程中重启了Vallotton，比如正好更新了版本。重新发送那句话即可。
一直停在「正在构思」大模型的官方接口连不上。可以在.env里配置备用线路OPENROUTER_API_KEY，官方接口不通时Vallotton会自动改走备用线路。设置页的「线路」里能看到当前用的是哪一条。
出图失败，错误里有「402」NovelAI账号里的点数（Anlas）用完了，通常是因为用了「高」画质。在生成设置里改回「中」。
NovelAI显示「状态未知」偶尔查不到NovelAI的账号状态，不影响画图，几分钟后会自己恢复。
MCP客户端超时把客户端的超时调到600秒以上。画图要等它画完才返回。
